Обоснование выбора разделов:
1. Есть несколько точек регистрации нового клиента, координации между этими точками нет; со стороны систем обработки данных нет ограничений на доступ к данным; уж есть проблемы с тем, что клиенты периодически видят не свои данные в ЛК - в проверочный лист надо включить раздел "управление доступом".
2. Партнёрские контракты передают персональные данные и допускают лишние действия; API управляющих компаний используются без единых политик безопасности и без системного контроля за передаваемыми данными - в проверочный лист надо включить раздел "безопасность данных"
3. Ландшафт гибридный: собственный ЦОД, приватное облако и мощности провайдера. Единый базовый уровень защиты должен действовать во всех средах и распространяться на веб-, мобильные и серверные компоненты; тем не менее сейчас присутствует проблема управления и хранения потоков данных, которая блокирует реализацию новых продуктов, основанных на данных в проверочный лист надо включить раздел "защита инфраструктуры"
4. Специалист по ИБ один на всю компанию, он. не получает сведения обо всех решениях, а передача информации между командами нарушена. Нужны централизованные события безопасности, порядок реагирования и обязательная проверка изменений; так же одна из потребностей бизнеса - отреагировать на инциденты и рыночные изменения - включаем в проверочный лист раздел "управление инцидентами".
